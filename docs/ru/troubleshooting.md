# Решение проблем и восстановление

[Документация](README.md) · [English](../troubleshooting.md) · [Установка](installation.md) · [Интеграции](integrations.md)

Начните с показанного отказа или ошибки: обычно ChakChak называет заблокированное действие и следующий шаг. Сохраните папку журнала запуска до изменения настроек или повторения сложного случая. Одного `journal.log` недостаточно для полной картины.

## Первые проверки

```sh
command -v chakchak
chakchak version
chakchak help
```

Команды определяют установку, не начиная миграцию. В нужном репозитории `chakchak specs` читает рабочую область без модели. `chakchak doctor` проверяет регистрацию навыков провайдера, но не исправляет загрузчики и не настраивает MCP. Рабочие команды, включая doctor/specs, могут создавать собственные журналы ChakChak.

Запишите версию/коммит, ОС и архитектуру, команду запуска, выбранную программу агента и модель, состояние репозитория, точное действие и видимый результат. Не включайте в отчёт API-ключи, токены и файлы авторизации провайдера.

## Приложение не запускается

| Симптом | Проверка и восстановление |
|---|---|
| Не та архитектура или формат исполняемого файла | `macos-arm64` — для Apple silicon, `macos-amd64` — для Intel. |
| macOS не разрешает запуск | Проверьте источник выпуска и соответствие архива `SHA256SUMS`. Выпуски подписаны и нотарифицированы; приложение, не прошедшее проверку, не является официальным выпуском. Снятие quarantine не заменяет проверку выпуска. |
| Ошибка чтения home/settings/импорта | Сохраните названный файл и переходите к [восстановлению состояния](#не-читается-сохранённое-состояние-или-настройки). Перед импортом закройте старые процессы. |
| Браузер не открывается | Используйте локальный адрес из вывода процесса. Проверьте, не занят ли экземпляр/порт другим ChakChak или другой программой. Не завершайте неизвестный процесс. |

Стандартный адрес — `127.0.0.1:7757`; это не удалённый сервис и не адрес MCP. Finder открывает собственное окно macOS, а `chakchak app` из терминала — браузер. Старая вкладка может указывать на прежний процесс: сравните адрес с текущим запуском.

## Не находится `chakchak` или агент

Для терминальной команды проверьте настройку **Команда в терминале**, `command -v chakchak` и `PATH`. Обычный файл в месте предполагаемой ссылки специально сохраняется. После перемещения приложения обновите ссылку и явно выполните `chakchak install`, если используете загрузчики навыка.

Сначала убедитесь, что программа агента сама запускается и авторизуется из терминала. ChakChak её не устанавливает и не авторизует. В приложении можно выбрать конкретную найденную копию. Сравните её путь с `command -v <program>`; журнал содержит заданный и разрешённый пути, если установка использует symlink.

Запуск с рабочего стола один раз добавляет недостающие переменные оболочки входа через `$SHELL -lic`, с ограничением десять секунд. Профиль, ожидающий ввод или долго работающий, может скрыть инструменты от приложения. Уберите интерактивные вопросы из файлов запуска оболочки, заново откройте ChakChak и проверьте событие импорта окружения. Не отправляйте полный вывод `env`: он может содержать секреты.

На macOS, если доступен только `/usr/bin/git`, а `xcode-select -p` не находит developer directory, ChakChak пропускает этот Git, чтобы не открыть системный диалог установки. Отдельно установленный Git продолжает использоваться. Если Git нельзя запустить, недоступны его список файлов/штамп исходников; чтение вне Git использует рабочее дерево.

## Агент падает, зависает или возвращает нечитаемый ответ

| Тип отказа | Значение и следующий шаг |
|---|---|
| `login` | Авторизация отсутствует, истекла или отклонена. Войдите средствами провайдера и продолжите. |
| `quota` | Лимит использования исчерпан. Дождитесь указанного сброса или решите вопрос лимитов, затем продолжите. |
| `overload` | Временная перегрузка. ChakChak повторяет вызовы с растущими паузами и уменьшает изученный темп. |
| `unknown model` | Проверьте каталог либо укажите модель, доступную установленному провайдеру/аккаунту. |
| `network` | Проверьте связь, proxy и DNS без раскрытия данных входа; продолжите после восстановления. |
| Нечитаемый/неверный ответ | Изучите полный вывод и определение провайдера. Несуществующий флаг, баннер CLI или новый JSON-формат может нарушить контракт. |
| Программа отсутствует | Установите/выберите исполняемый файл и перезапустите: возобновление в том же процессе не возвращает исчезнувшую программу. |

При записи спецификаций login, quota, network и повторяющиеся одинаковые необъяснённые отказы приостанавливают волну, сохраняя готовые спецификации. Терминал предлагает Enter для продолжения или `q`, страница — **Продолжить**. Пауза записывается в `run.json`; новый запуск выполняет оставшуюся работу. Отсутствующий агент/OpenSpec вместо паузы завершает соответствующие спецификации с ошибкой и позволяет дойти до отчёта с причиной.

Для потокового чтения действует предел десять минут без вывода; для любого чтения — общий час. Запись артефакта изменения ограничена 20 минутами, задачи — 60 минутами. Это пределы, а не обычная длительность. Работающий процесс может быть медленным без зависания: смотрите его поток и события журнала. Проваленный этап останавливает автопилот до явного повтора, а не повторяет бесконечно.

Диагностика неудачного вызова включает программу, замаскированные аргументы, exit/signal, размеры потоков и последние строки. Журнал ссылается на полные потоки, сохранявшиеся во время работы. Если обновление внешнего CLI изменило флаги, задайте полную строку в `~/.chakchak/agents.json` и перезапустите; см. [замены провайдеров](integrations.md#собственные-провайдеры-и-замены). Не добавляйте вслепую обход разрешений для исправления чтения.

## MCP подключён, но работа не движется

Убедитесь, что клиент запускает абсолютный путь с `mcp` через **stdio** в нужном репозитории. `chakchak install` это соединение не создаёт. URL браузера не является MCP endpoint. Старый загрузчик или запись клиента может указывать на перемещённое приложение.

Пассивное соединение не начинает работу: вызовите `start`, затем прочитайте `status`. `busy` означает, что репозиторием владеет другая рабочая сессия; завершите её и повторите `start` в том же соединении. Простое чтение списка инструментов другим клиентом не захватывает папку.

В session mode (`mcp` без провайдера) управляющий агент должен получать `tasks` и возвращать каждый `answer`. `tasks_taken` при отсутствии работающего исполнителя обычно означает потерянное задание; `tasks {retake: true}` выдаст задания без ответа снова. В режиме провайдера (`mcp codex`, например) работу делает внешний CLI, а очередь намеренно недоступна.

После отказа из-за устаревшего `revision` заново прочитайте `status` и оцените вопрос. Не повторяйте старое решение автоматически. `fix` и `rule` возвращаются до завершения работы: проверяйте `commands` и обслуживайте задания. После `status.wait` с результатом `unchanged` можно ждать снова; `idle` требует действия клиента. Единственное число `task` и `artifact` лишь возвращают промпты и ничего не запускают.

## Репозиторий занят или действие недоступно

Репозиторием владеет один рабочий запуск. Запись изменения/задачи также удерживает границу записи: миграция, синхронизация, повтор и смена агента могут быть недоступны до её завершения. Используйте Stop работающей сессии или дождитесь окончания. Stop не откатывает правки; проверьте `git diff` и коммиты задачи.

После падения откройте репозиторий обычным способом. Перед использованием ChakChak завершает оставшийся процесс записи предыдущего запуска. Не удаляйте lock-файлы и `checkpoint`, чтобы протолкнуть конкурирующий процесс. Действие схемы, артефакта или задачи может быть недоступно из-за незавершённого шага, ожидания подтверждения или изменившегося текста. Перечитайте рабочую область и сначала разберите названный шаг.

Если `openspec/` относится к родительской папке, а не к выбранному репозиторию, ChakChak откажет. Работайте в нужном корне Git. Для эксперимента с вложенным образцом скопируйте его за пределы родительского репозитория и создайте в копии отдельный Git-репозиторий.

## Спецификации красные, файлы отсутствуют или синхронизация ничего не делает

Рабочая область сравнивает хеши рабочего кода и спецификаций с **последней сверкой**, а не только время файлов. Изменённая/отсутствующая спецификация, изменённый рабочий файл, потерянный trace/check или нечитаемая сверка могут нарушить актуальность. Посмотрите `chakchak specs` и отчёт для затронутых возможностей.

| Наблюдение | Ожидаемое поведение или восстановление |
|---|---|
| Новый файл отсутствует | Git-untracked игнорируются; добавьте файл в индекс, когда он должен стать частью проекта. Проверьте также сохранённую область чтения. |
| Новая верхнеуровневая папка игнорируется | Синхронизация сохраняет исходную область, не расширяя её автоматически. Изменение области после миграции пока не предлагается. |
| Правка теста/ресурса не запускает синхронизацию | Их содержимое не составляет базу хешей рабочего кода; добавление/удаление всё же может учитываться. |
| Возможность помечена активным изменением | Она ждёт, пока её называет неархивированное изменение; синхронизация её не переписывает. Завершите/архивируйте или иначе разрешите изменение обычным процессом. |
| Изменение rules/context не переписало спецификации | Оно само по себе не меняет актуальность. Чтобы намеренно применить его ко всем спецификациям, используйте `chakchak stage specs --all`. |
| Миграция продолжается вместо синхронизации | Запуск без законченного отчёта ещё не завершён. Сначала продолжите и проверьте его. |
| Все спецификации стали неактуальными | Проверьте потерю `reconciliation.json`, trace/check или состояния. При необходимости восстановите намеренно сохранённые в Git данные; полная перезапись потребует модельных вызовов. |

Не удаляйте `openspec/chakchak/` как универсальный сброс: это удаляет идентичность миграции и может начать новую поверх существующих спецификаций. Случайно удалённое сохранённое состояние восстанавливайте через Git, предварительно проверив, что заменится, и сохранив текущие правки. Ручная спецификация — материал для следующего автора, а не более сильная истина, чем код; проверяйте итоговый diff.

## Продолжить разговор или начать новый

Клон, новый компьютер или другой провайдер могут продолжить обсуждение по результату из `run.json`. Если старого разговора провайдера нет, ChakChak один раз создаёт новый на сохранённом контексте и пишет `talk continued` с `reason=session-missing`; смена агента отмечается `reason=agent-changed`. Читаемый результат есть в `talk.md`; контекст проекта редактируйте в `openspec/config.yaml`, а не в этом производном файле.

Для намеренно нового разговора:

```sh
chakchak new-conversation
```

Команда спрашивает подтверждение; `--confirm` передаёт явное подтверждение для скрипта. Точный старый `checkpoint` сохраняется в `openspec/chakchak/before-restore/`; этап, обсуждение, спецификации и результаты остаются. Если архивирование или новый вызов провайдера не удался, активный `checkpoint` сохраняется. MCP `restart_conversation` требует revision/proof из status и `confirmed: true`.

## Не читается сохранённое состояние или настройки

Перед первым рабочим запуском новой версии закройте старые процессы ChakChak. Импорт использует прежние настройки/историю только как источники; корректное назначение имеет приоритет. Обязательные повреждённые/неполные данные сохраняются, а открытие останавливается с указанием пути. Копирование старых логов по возможности может предупредить об ошибке, оставив источник следующему запуску.

До исправлений сохраните названные источник и назначение. Для некорректного `~/.chakchak/settings.json` верните хорошую копию либо исправьте JSON при закрытом ChakChak: запись специально отказывается затирать повреждённые байты. Не заменяйте файл на `{}`, не сохранив его. Неизвестные ключи настроек писатель оставляет.

Старый кеш может оставаться в `~/Library/Caches/chakchak/` на macOS. Это не текущая среда, но он не удаляется автоматически: там могут быть незаконченные импорты и история клиентов. История репозиториев из `~/.chakchak/projects/` переносится внутрь репозитория после сохранённого согласованного запуска. Повторное удаление home/cache скрывает доказательства и не чинит `checkpoint` репозитория.

## Не удаётся обновление

Завершите активную работу, переместите translocated-приложение Mac в Applications и проверьте право записи в родительскую папку. Обновление откажет без архива платформы, без/с неверным `SHA256SUMS`, при неправильной версии программы, недействительной подписи macOS или другом Team ID. Используйте подходящий подписанный дистрибутив, не обходите проверки.

Development-сборки могут не проверять обновления автоматически. Собственную сборку обновляйте по инструкции того, кто её предоставил. После замены закройте и заново откройте всё ещё работающую старую копию.

## Собрать доказательства без раскрытия секретов

Путь журнала печатается при старте/закрытии и повторно при переносе. Основные места:

```text
~/.chakchak/logs/<launch>/
<repository>/openspec/chakchak/logs/<launch>/
```

Для приватного расследования сохраните **всю папку запуска** и упомянутые снимки/состояния before-restore. В ней могут быть:

| Доказательство | Что объясняет |
|---|---|
| `journal.log` | Действия, переходы, отказы, процессы, ссылки на файлы доказательств |
| `stdout.txt`, `stderr.txt` | Точный терминальный вывод, неполные приглашения, управляющие байты |
| `calls.jsonl`, task/answer и stdout/stderr процессов | Модели, время, полные задания/ответы и диагностика |
| Нумерованные verification-артефакты | Замечания к конкретным хешам спецификаций, включая прежние версии |
| Репозиторные `trace.jsonl`, `verify.jsonl`, `report.md` | Основа текущей спецификации, проверка сценариев и открытая работа |

Сырые папки могут содержать исходный код, промпты, ответы, введённый текст, локальные пути и секреты, напечатанные инструментами. Это не очищенный пакет для поддержки. Важные доказательства копируйте своевременно: при открытии или переходе в каталог журналов очистка сохраняет 20 самых новых папок запусков и все запуски, изменённые за последние семь дней, а также текущую/исходную папку запуска и папки с живой блокировкой журнала. Остальные подходящие старые папки могут удаляться. Правило касается папок с журналом, а не произвольных каталогов, снимков или разговоров. Другую историю удаляйте или архивируйте только после сохранения нужного и закрытия соответствующего запуска.

Экран отчёта разработчику собирает **очищенный текст с предпросмотром** из выбранных групп: окружение, проблемы, хронология, модельные вызовы и падение. Он убирает поля с текстами модели/человека/файлов, заменяет локальные пути/личные данные и маскирует известные форматы секретов. Отправляется показанный текст с отдельно очищенным комментарием. Проверьте оба: произвольные имена и секреты нельзя гарантированно распознать шаблонами. Не вставляйте сырые журналы в комментарий.

Отправка — явное действие на настроенный feedback endpoint; автоматической выгрузки сырой папки нет. Стандартный адрес задан в сборке приложения; `CHAKCHAK_FEEDBACK_URL` позволяет указать свой. Вызовы провайдера и проверка выпусков GitHub — отдельная сетевая активность.

Для полезного issue приложите минимальное воспроизведение, ожидаемое/фактическое поведение, версию и выбранную программу, видимый отказ и просмотренный отчёт/отрывок. Сырые доказательства храните приватно до согласованной потребности в них. Завершённая миграция может иметь неподтверждённые сценарии или незаконченную проверку: укажите их как открытые замечания, а не считайте exit 0 доказательством каждого утверждения.
