# Установка и обновление

[Документация](README.md) · [English](../installation.md) · [Интеграции](integrations.md) · [Решение проблем](troubleshooting.md)

ChakChak работает локально и вызывает CLI агента, который вы устанавливаете и авторизуете отдельно. Готовое приложение включает обычный OpenSpec и среду Bun для его запуска. Node, Bun и глобальная установка OpenSpec для такого приложения не нужны.

## Выбор дистрибутива

| Дистрибутив | Требования | Доступность |
|---|---|---|
| Приложение macOS, Apple silicon | macOS 12 или новее, Mac с процессором Apple M | `ChakChak-<version>-macos-arm64.zip` |
| Приложение macOS, Intel | macOS 12 или новее, Intel Mac | `ChakChak-<version>-macos-amd64.zip` |
| Бинарный файл/архив Linux | Linux amd64 или arm64; упакованный бинарный файл не должен требовать glibc новее 2.34 | Готовые Linux-архивы сейчас не публикуются |
| Windows | — | Поддерживаемой сборки и выпуска нет |

Для двух архитектур Mac выпускаются отдельные приложения, а не universal binary. [Репозиторий выпусков](https://github.com/arkuramshin/ccr/releases) — стандартный источник загрузок и обновлений; собственная сборка может использовать другой репозиторий или отключить проверку. В [последнем выпуске](https://github.com/arkuramshin/ccr/releases/latest) выберите архив своей архитектуры. Автоматические GitHub-архивы **Source code** содержат этот репозиторий документации, а не готовое приложение.

Нужен доступ на чтение и запись в рабочий репозиторий. Рекомендуется Git: ChakChak читает отслеживаемые файлы, включая добавленные в индекс, а Git позволяет проверить и восстановить результат. Папка вне Git читается как рабочее дерево. Для модельных вызовов нужны учётная запись агента и связь с его провайдером; карта кода и сравнение состояния спецификаций модель не вызывают.

## Установка приложения macOS

1. Скачайте ZIP для архитектуры своего Mac и `SHA256SUMS` из того же выпуска.
2. Проверьте архив командой ниже. Если скачана только одна архитектура, проверка может сообщить об отсутствии второй. Убедитесь, что именно устанавливаемый ZIP имеет результат `OK`.
3. Распакуйте архив и переместите `ChakChak.app` в `/Applications` или собственную папку `~/Applications` до использования обновлений.
4. Откройте приложение. Запуск из Finder открывает собственное окно ChakChak. Выберите установленного агента, затем репозиторий.

```sh
shasum -a 256 -c SHA256SUMS
```

Исполняемый файл находится в `ChakChak.app/Contents/MacOS/chakchak`. OpenSpec и `THIRD_PARTY_NOTICES.md` лежат в `Contents/Resources/`. Приложение использует свой OpenSpec независимо от другой команды `openspec` в `PATH`.

Подписанное приложение проверяет macOS. Архив с `-unsigned` в имени содержит локальную/ad-hoc сборку и не равнозначен подписанному нотарифицированному выпуску. Если система не разрешает запуск, см. [решение проблем запуска](troubleshooting.md#приложение-не-запускается).

## Команда в терминале

При запуске из пакета macOS ChakChak пытается создать символическую ссылку `chakchak` на свой исполняемый файл. Сначала используется доступный для записи `/usr/local/bin`, затем `~/.local/bin`; на Linux первым проверяется `~/.local/bin`. В настройке **Команда в терминале** показан путь и доступно создание ссылки, если при запуске оно не удалось.

Ссылка на старую копию может быть обновлена. Обычный файл с именем `chakchak` сохраняется: прежде чем заменять его, проверьте существующую установку. Настройки также показывают команду для создания ссылки в `/usr/local/bin` с правами администратора.

Если ссылка оказалась в `~/.local/bin`, добавьте эту папку в `PATH`. Для zsh поместите строку в профиль входа `~/.zprofile` и откройте новый терминал:

```sh
export PATH="$HOME/.local/bin:$PATH"
```

Проверьте, какая команда запускается:

```sh
command -v chakchak
chakchak version
```

Версия включает выпуск и коммит, например `chakchak <version> (<commit>)`; у сборки изменённого дерева может быть суффикс `-dirty`. Те же сведения видны в настройках приложения. `version`, `help` и `skill` не создают домашнюю папку или журнал.

## Установка Linux из собранного архива

Готовые выпуски сейчас доступны только для macOS. Если у вас уже есть Linux-архив от сборщика, следуйте инструкциям ниже. Исходников приложения в этом репозитории нет; скачать и собрать приложение из архива **Source code** здесь нельзя.

Архив содержит одну папку с `chakchak`, `THIRD_PARTY_NOTICES.md`, `chakchak.desktop` и `chakchak.png`. Бинарный файл включает OpenSpec. Упаковщик проверяет, что требуемые версии символов glibc не выше 2.34; системы только с musl не являются целью этой упаковки.

Для архива с соответствующим манифестом подставьте настоящую версию и архитектуру:

```sh
sha256sum -c --ignore-missing SHA256SUMS
tar -xzf chakchak-<version>-linux-amd64.tar.gz
cd chakchak-<version>-linux-amd64
mkdir -p "$HOME/.local/bin"
install -m 0755 chakchak "$HOME/.local/bin/chakchak"
install -Dm 0644 chakchak.desktop "$HOME/.local/share/applications/chakchak.desktop"
install -Dm 0644 chakchak.png "$HOME/.local/share/icons/hicolor/256x256/apps/chakchak.png"
chakchak version
```

Сохраняйте уведомления о сторонних компонентах вместе с дистрибутивом. Ярлык запускает `chakchak app`, поэтому графическая сессия должна находить `chakchak` через `PATH`; изменение только shell-профиля может не повлиять на уже открытую сессию рабочего стола. Запуск `chakchak app` из терминала открывает локальный интерфейс в браузере.

## Первый рабочий запуск

Сначала установите агента и войдите в него его собственными средствами. ChakChak этого не делает. В [руководстве по интеграциям](integrations.md#провайдеры) перечислены встроенные определения провайдеров и настройка собственных программ.

Выберите способ запуска:

```sh
chakchak app                         # выбрать репозиторий в приложении
cd /absolute/path/to/your/repository
chakchak web codex                   # браузерный интерфейс репозитория
chakchak cli codex                   # терминальный интерфейс
chakchak cli claude --lang ru        # обсуждение, спецификации и отчёт по-русски
```

Замените `codex` или `claude` своей программой. В приложении агента нужно выбрать явно. Терминальный запуск может использовать указанного агента или доступный/сохранённый выбор. Настройки сохраняют агента и путь программы; выбор модели в приложении живёт в памяти. Подробности модели, языка и параллелизма — в разделе [команд и значений по умолчанию](integrations.md#команды-и-флаги).

Стандартный локальный адрес — `127.0.0.1:7757`. Используйте адрес, который фактически напечатан при запуске. Сервис слушает loopback и предназначен для этого компьютера. `app` из терминала открывает браузер; Finder открывает приложение в собственном окне с тем же интерфейсом.

Перед началом миграции проверьте репозиторий и область чтения. Сгенерированные файлы, зависимости и каталоги сборки изначально исключены по встроенным подсказкам и `.gitignore`. Файлы вне индекса Git не попадают в карту, пока не добавлены в индекс. Миграция и дальнейшие изменения описаны в [руководстве приложения](manual.md).

## Где хранятся данные

| Путь | Назначение |
|---|---|
| `~/.chakchak/settings.json` | Недавние репозитории, агент/программа, собственные команды вызова, язык, изученный темп и время, кеш проверки обновлений; не данные входа провайдера |
| `~/.chakchak/agents.json` | Необязательные дополнения и замены определений провайдеров |
| `~/.chakchak/SKILL.md` | Полная актуальная инструкция агенту, обновляемая при рабочих запусках |
| `~/.chakchak/logs/<launch>/` | Запуски до сохранения согласованного состояния репозитория, служебные команды и старт приложения |
| `~/.chakchak/runtime/openspec/` | OpenSpec, распакованный бинарным файлом с `BUNDLED=1`; `.app` запускает копию внутри пакета |
| `~/.chakchak/runtime/from/<name>-<key>/` | Временные файлы среды/ответов репозитория, удаляемые при нормальном завершении; соседний `.repository` указывает исходную папку |
| `<repository>/openspec/` | Конфигурация OpenSpec, основные спецификации, изменения и долговременное состояние миграции |
| `<repository>/openspec/chakchak/logs/` | Журналы после согласия/сохранённого запуска; при переносе журнала печатается новый путь |
| `<repository>/openspec/chakchak/{conversations,snapshots,before-restore}/` | Локальная история запуска, исключённая из коммитов через `.gitignore` ChakChak |

Репозиторий узнаётся по сохранённому содержимому, а не по реестру в домашней папке. Клон или перемещённая папка с `openspec/chakchak/run.json` распознаётся как существующая миграция; коммитьте долговременные результаты OpenSpec, необходимые коллегам. Локальные журналы и снимки обычно не попадают в клон. До согласия пользователя в новый репозиторий ничего не записывается.

Старые установки могут импортировать настройки и историю из предыдущих каталогов конфигурации/кеша. Перед обновлением закройте старые процессы. Импорт сохраняет повреждённые/неполные источники и отказывается от небезопасной замены; старые кеши не удаляются автоматически. См. [восстановление](troubleshooting.md#не-читается-сохранённое-состояние-или-настройки).

## Обновление готового приложения

Выпуск с настроенным репозиторием обновлений проверяет GitHub при `app` не чаще раза в сутки; в настройках есть ручная проверка. Development-сборки и сборки с `RELEASES=` не проверяют обновления. Сбой сети или лимит GitHub не мешают работе с репозиторием; временные ошибки запроса повторяются ещё два раза через 2 и 5 секунд.

Действие **Обновить** скачивает подходящий архив и `SHA256SUMS`, проверяет сумму и версию, заменяет программу/приложение и перезапускает его по прежнему локальному адресу. На macOS дополнительно обязательны успешная `codesign --verify --deep --strict` и совпадение Team ID с текущим приложением. При сбое перестановки пакета возвращается старая копия. На Linux применяется проверка суммы без проверки подписи macOS.

Обновление не начинается во время работы, из translocated-приложения macOS, в недоступную для записи папку, без подходящего архива или без манифеста сумм. Переместите приложение в Applications, завершите/остановите активную работу и используйте доступное место установки. Linux не может обновиться из выпуска без Linux-архива. Разберите причину отказа, не заменяйте файлы во время миграции.

## О сборках из исходников

Этот репозиторий содержит документацию и готовые выпуски. Для самостоятельной сборки нужен отдельный доступ к исходникам ChakChak и инструкции из того репозитория. Здесь нет каталога `App` и целей `make`.

Development-сборке без встроенного OpenSpec нужна команда `openspec` в `PATH`; готовое приложение включает OpenSpec. Собственная сборка может отключать проверку обновлений: обновляйте её по инструкции того, кто её предоставил.

## Удаление

Если устанавливали загрузчики навыка для агентов, выполните `chakchak uninstall` до удаления исполняемого файла. Команда удаляет только точные неизменённые загрузчики этой установки и сообщает о сохранённых чужих/изменённых файлах. Конфигурацию MCP-клиентов, приложение, терминальные ссылки, историю провайдеров, настройки и спецификации она не удаляет.

Закройте ChakChak, удалите приложение/бинарный файл и указывающую на него терминальную ссылку, затем удалите его MCP-запись в настроенных клиентах. Сохраните `openspec/`, если продолжаете пользоваться спецификациями. Перед удалением `~/.chakchak/` или диагностических/исторических папок репозитория сделайте резервную копию нужных данных. Uninstall их не стирает; отдельная [политика хранения журналов](troubleshooting.md#собрать-доказательства-без-раскрытия-секретов) удаляет только подходящие старые папки запусков.
