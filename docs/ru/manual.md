# Руководство пользователя ChakChak

[Документация](README.md) · [English](../manual.md) · [Установка](installation.md) · [Интеграции](integrations.md) · [Решение проблем](troubleshooting.md)

ChakChak помогает перевести существующий репозиторий кода на разработку на основе спецификаций. Приложение читает реализацию, уточняет с вами назначение проекта, распределяет файлы по возможностям системы — capabilities — и создаёт обычные спецификации OpenSpec. Затем в нём можно планировать изменения, проверять документы, выполнять задачи через своего агента программирования и архивировать завершённые изменения.

Руководство описывает окно приложения и браузерный интерфейс. Они работают с одним локальным процессом ChakChak и теми же файлами репозитория. Это то же руководство, которое приложение показывает в **Справка → Руководство**, офлайн и на языке интерфейса.

## 1. Что создаёт ChakChak

**Capability** — наблюдаемый результат или обязанность системы: например, поиск в каталоге, оформление корзины или сохранение документа. Её спецификация описывает требования и сценарии, а не повторяет список классов и методов. Код одного результата может принадлежать одной capability, даже если он включает интерфейс, бизнес-логику и хранение данных.

Основные результаты работы:

| Файл или папка | Назначение |
| --- | --- |
| `openspec/config.yaml` | Контекст проекта и правила для подготовки спецификаций и изменений. |
| `openspec/specs/<capability>/spec.md` | Основная спецификация capability. Имя может включать папки областей. |
| `openspec/chakchak/report.md` | Результаты миграции или сверки, включая незавершённую работу и замечания. |
| `openspec/chakchak/` | Карта кода, распределение файлов, сохранённое состояние, связи спецификаций с кодом и данные восстановления. |
| `openspec/changes/<name>/` | Документы и дельта-спецификации активного изменения. |
| `openspec/changes/archive/` | Архив изменений. |

Спецификации остаются обычными файлами OpenSpec. Их можно читать в редакторе, проверять через Git и использовать со стандартными инструментами OpenSpec. Данные ChakChak добавляют навигацию и восстановление, но не заменяют сами спецификации.

Машинные проверки устанавливают, что объявления кода учтены, а структура спецификации корректна. Отдельная модель проверяет сценарии по коду. Это помогает разобрать результат, но не доказывает истинность каждого утверждения и не означает, что тесты программы прошли.

## 2. Перед первым запуском

Нужны локальный репозиторий и установленный CLI агента программирования, в котором вы уже вошли в аккаунт и который работает из терминала. ChakChak использует аккаунт и доступные модели этой программы. Релиз включает OpenSpec и среду его выполнения; сборке для разработки может понадобиться `openspec` в `PATH`.

Текущий процесс выпуска публикует пакеты для Mac с Apple silicon и Intel. Перед запуском перенесите `ChakChak.app` в «Программы».

Подготовьте репозиторий перед выполнением задач агентом:

1. Выберите корень репозитория, а не случайную вложенную папку большого проекта.
2. Проверьте состояние Git и сохраните исходное состояние важной работы, к которому можно вернуться.
3. Добавьте в Git исходники, которые должны участвовать в миграции. Файл может быть добавлен в индекс без коммита, но неотслеживаемые файлы не входят в обычную карту кода.
4. Убедитесь, что выбранный агент может читать репозиторий. На macOS приложению и агенту могут требоваться отдельные разрешения «Файлы и папки».

Для миграции не нужно собирать проект. Поддерживаются парсеры Swift, Objective-C, Java, Kotlin, Python, Go, JavaScript, TypeScript и TSX. Файлы других форматов могут попасть в список, но не дают разобранных объявлений для проверки покрытия спецификациями.

## 3. Открытие репозитория и выбор агента

### Запустите приложение

Откройте ChakChak обычным способом или выполните:

```sh
chakchak app
```

Приложение из пакета macOS открывает собственное окно. При запуске из терминала локальный интерфейс обычно открывается в браузере. Если браузер не открылся, перейдите по локальному адресу, который напечатала команда.

Первый экран содержит репозитории и доступных агентов. В **Репозиториях** нажмите **Выбрать папку**, если система предоставляет диалог выбора, либо введите абсолютный путь в разделе **Добавить репозиторий** и нажмите **Добавить**. Кнопка **Открыть** у недавнего репозитория сразу открывает его; выбор строки сначала показывает сведения. **Забыть** удаляет запись из списка, сохраняя папку на диске.

Следующий экран зависит от содержимого репозитория:

| Состояние репозитория | Что откроется |
| --- | --- |
| Локального рабочего пространства OpenSpec нет | Начало миграции. |
| Есть незавершённая миграция ChakChak | Её сохранённый этап. |
| Есть локальное рабочее пространство OpenSpec без незавершённой миграции | Рабочее пространство SDD. |

Список недавних папок служит удобству на этом компьютере. Перемещённый или клонированный репозиторий распознаётся по собственным файлам ChakChak.

### Выберите программу и модель

Откройте ячейку агента и нажмите **Выбрать**. ChakChak различает несколько установленных копий программы по путям к исполняемым файлам. **Проверить** запрашивает у этой копии список моделей; для выбора агента ждать загрузки списка необязательно. На первом экране модели показаны для информации. Модель выбирается в настройках запуска или соответствующем поле ввода.

Чтобы добавить провайдера, откройте **Новый провайдер**, введите имя программы или абсолютный путь к ней и нажмите **Добавить**. Для известного провайдера отдельная команда не нужна. Незнакомому провайдеру может понадобиться шаблон команды с `{task}` и, если поддерживается, `{model}`. При добавлении ChakChak может запустить программу, чтобы определить способ передачи задания. Поддержка провайдера и набор моделей зависят от установленного CLI.

Выбранный агент и путь к программе сохраняются на этом компьютере. Этот выбор имеет приоритет и при открытии сохранённого запуска; записанный в запуске агент используется, если выбора нет или выбранная программа исчезла. В приложении **Настройки → Этот запуск** позволяют сменить агента, когда работа остановлена. Если переключение недоступно, элемент управления объясняет причину. При смене агента принятые результаты сохраняются; при необходимости разговор начинается заново с сохранённым контекстом.

Выбор модели хранится только в работающем приложении, отдельно для каждой копии программы. Он применяется к следующим вызовам, в том числе если выбрать модель во время текущей работы; уже выполняющийся вызов не меняется. Перезапуск ChakChak сбрасывает эти выборы, поэтому перед продолжением проверьте модель, если нужна конкретная. Пустой выбор использует модель по умолчанию самого агента.

На странице, запущенной через `chakchak web`, агент не меняется на месте: остановите процесс и запустите его с нужным агентом и моделью. Страница миграции, которой управляет внешний агент, преимущественно доступна для просмотра и сообщает, кто ведёт работу.

## 4. Навигация по интерфейсу

Верхняя панель показывает репозиторий и открывает помощь и настройки. Слева в **сотах** находятся этапы, спецификации, изменения или шаги процесса. Справа **рабочая область** показывает выбранный объект.

- Выберите этап или шаг, чтобы посмотреть его. Повторное нажатие на выбранный этап может открыть вызовы модели. В подробностях вызова доступны запрос, ответ, время и результат.
- Откройте спецификацию или файл для чтения в рабочей области. **Назад** или Escape возвращает к предыдущему экрану.
- Заголовок Requirement или Scenario со ссылкой открывает связанный код. Для сценария это могут быть строки, сохранённые во время проверки; представление объявлений читает текущий исходник и отмечает изменения.
- Нажмите правую кнопку мыши на объекте или Shift+F10 на объекте с фокусом, чтобы открыть доступные действия: открыть, показать файл, скопировать имя или путь.
- **Настройки → Анимация → Меньше эффектов** заменяет анимированные соты боковым списком и отключает движение. Такой же список используется, если графическое представление не может работать.

Окна и вкладки одного приложения используют общий выбранный репозиторий и основной экран. Переход в одном окне может переключить остальные. Черновики ответов привязаны к своему репозиторию и вопросу.

Открытие документа не запускает новый вызов модели. Если локальный процесс перестаёт отвечать, страница сохраняет последние данные, показывает уведомление о соединении и отключает действия, которым нужен сервер.

## 5. Начало миграции и выбор языка

На стартовом экране изучите дерево репозитория и описание того, что нашёл ChakChak. Нажмите **Начать**, чтобы запустить миграцию. До этого согласия приложение не создаёт результаты миграции в репозитории.

Если страница предлагает **git init**, действие создаёт Git-репозиторий, добавляет его текущее содержимое в индекс и делает первый коммит с вашей Git-идентичностью. Сначала проверьте папку и правила игнорирования: действие охватывает содержимое в его текущем виде. Исправьте указанную ошибку Git или настройки автора перед продолжением.

Язык интерфейса и язык спецификаций выбираются независимо:

| Настройка | На что влияет | Можно изменить во время запуска? |
| --- | --- | --- |
| Язык интерфейса | Кнопки, навигация, сообщения и это руководство. | Да. |
| Язык спецификаций | Обсуждение, описание проекта и capabilities, спецификации и отчёт. | Только пока запуск не вышел из подготовки. |

Перед началом установите **Настройки → Этот запуск → Язык спецификаций**. Поддерживаются русский и английский. После фиксации язык сохраняется при повторах, перезапусках и смене агента. Переключение интерфейса не переводит созданные документы. Маркеры OpenSpec — `Requirement`, `Scenario`, `WHEN`, `THEN`, — пути и идентификаторы сохраняют техническую форму и в русских документах.

## 6. Карта кода: определите область миграции

Последовательность миграции — **map → talk → picture → cut → specs → report**: карта кода, обсуждение, описание проекта, распределение, спецификации, отчёт. В приложении обсуждение и описание проекта объединены в **Обзор репозитория**.

Этап **Карта кода** собирает файлы и объявления. Проверьте количество файлов продукта, тестов, файлов без разбора и элементов кода. Если числа неожиданны, откройте карту или список неразобранных файлов. Оценка числа вызовов и времени приблизительна: на длительность влияют скорость модели, исправления и ваше время на проверку.

Флажками папок выберите продукт, который нужно описать. Раскройте папку, чтобы уточнить выбор внутри неё. Зависимости, сгенерированные файлы, кеши и результаты сборки изначально исключаются, когда их определяют правила по умолчанию или корневой `.gitignore`. Например: `vendor`, `node_modules`, `Pods`, `build`, `target`, `dist`, `generated`. Папку можно включить явно, если она относится к вашему продукту.

Большинство случаев пропавших файлов объясняется тремя правилами:

1. В Git-репозитории карта использует отслеживаемые файлы, включая только что добавленные в индекс. Выполните `git add` для неотслеживаемого исходника; одного создания файла недостаточно.
2. Исключённые папки не добавляют файлы и объявления в подготовленные задания миграции, распределение и связи спецификаций с кодом.
3. Неподдерживаемые исходники и ресурсы не разбираются на объявления. Выбор папки не добавляет парсер её языка.

Если пригодного списка Git нет, папка может читаться как рабочее дерево. Нужен поддерживаемый исходник продукта. Если в корне есть папки, нельзя снять флажки со всех и рассчитывать только на исходники в корне: выберите хотя бы одну папку с кодом продукта.

**Тесты — тоже продукт** подходит репозиторию автоматизации или тестовой платформы, чей результат и есть тесты. Обычно тесты поддерживают capabilities основного кода. При включённом переключателе разобранные тестовые файлы считаются кодом продукта для учёта и спецификаций. ChakChak может включить его сам, если выбранные папки содержат тесты, но не содержат основного кода; ваш явный выбор сохраняется.

После проверки нажмите **Продолжить**, чтобы открыть обзор репозитория. Выбор сохраняется в `openspec/chakchak/scope.json`. Позднейшая сверка использует его и не включает новую корневую папку автоматически. Изменение установленной области после миграции через приложение пока не предлагается. Старые запуски без файла области сохраняют прежнее поведение.

Область определяет состав карты и подготовленных материалов миграции. Она не ограничивает доступ процесса агента к файловой системе.

## 7. Обзор репозитория: рассказ, вопросы и описание проекта

### Дайте исходный контекст

После карты обзор открывается с приглашением рассказать о проекте. Опишите, что делает продукт, кто им пользуется, какие термины важны и что трудно понять из кода. При необходимости приложите материалы. Поле можно оставить пустым: нажмите **Начать анализ**, чтобы модель сначала изучила код.

Полезны конкретные сведения: «Сервис резервирует остатки для заказов партнёров; оплатой занимается другая система». Отделяйте будущие намерения от уже реализованного поведения.

### Ответьте на вопросы или завершите уточнение

Модель может задать вопросы и предложить ответы. Выберите предложение или напишите свой ответ. Перед отправкой проверьте собранные ответы. **Завершить уточнение** заканчивает обсуждение с уже установленными сведениями. При нажатии из исходного рассказа эта кнопка выполняет первичный анализ и принимает предложенные моделью ответы. Вопрос без ответа не считается подтверждённым вами.

Если анализ не удался, используйте повтор именно этой операции. Рассказ, вложения и отправленные ответы сохраняются. Неудавшийся ответ повторяется с теми же словами, пока вы явно их не замените.

### Примите описание проекта

**Описание проекта** — результат этапа picture: связный рассказ о проекте, который записывается в `context` файла `openspec/config.yaml`. Прочтите его и исправьте неверные границы, пользователей, термины или обязанности. Просмотрите правила спецификаций, если они показаны рядом.

Нажмите **Продолжить**, чтобы принять описание. Обычная интерактивная миграция после этого ждёт инструкций к распределению; принятие описания само по себе не запускает этот вызов модели.

Если в существующем рабочем пространстве уже есть контекст проекта, ChakChak может использовать его и пропустить обзор. При позднейшей сверке **Обсудить заново** явно возвращает к обсуждению.

## 8. Распределение: сгруппируйте файлы по capabilities

На остановке перед распределением опишите границы, которые важно сохранить: что объединить, что разделить и какой общий код является самостоятельной возможностью продукта. Нажмите **Начать распределение** с инструкциями или без них. Непустые инструкции сохраняются как правила этого этапа.

Модель предлагает дерево capabilities и помещает разобранные файлы в них либо в `support`. В support попадают файлы без самостоятельного поведения продукта, которое нужно описать. Тесты обычно следуют за проверяемой capability. Крупные capabilities могут дополнительно читаться моделью, чтобы выделить отдельные результаты; отметка «сохранена целиком после чтения» с объяснением сама по себе не означает ошибку.

Проверьте дерево перед принятием:

1. Раскройте capabilities и посмотрите файлы. Сопоставьте группы с результатами, понятными пользователю или вызывающему коду.
2. Изучите замечания к покрытию: особенно нераспределённые файлы и повторные назначения. Перед принятием каждый файл карты должен иметь одно итоговое место.
3. При необходимости переместите файл или папку. Проверьте предварительный результат и нажмите **Применить**. Перемещение может захватить связанные тесты.
4. Для более широкого исправления опишите нужное изменение в обсуждении распределения. Новое предложение использует принятое описание проекта и ваши слова.

Некоторые дефекты ответа проходят одну автоматическую попытку исправления до показа предложения. Оставшиеся замечания видны при проверке. Принятие распределения с допустимыми замечаниями сохраняет их в отчёте. Распределение с пропущенными или повторно размещёнными файлами принять нельзя.

Во время дополнительных чтений **К проверке** останавливает чтение, сохраняет завершённые результаты и открывает предложение. **Читать дальше** запускает оставшиеся чтения. Если принять распределение без завершения необходимых чтений, затронутые capabilities могут быть отложены без написания спецификации.

Принятие распределения в обычной интерактивной миграции открывает ещё одну остановку — перед спецификациями. При необходимости задайте термины предметной области и правила написания, затем нажмите **Начать написание спецификаций**. Сверка, автопилот и запуск без участия человека могут проходить эти дополнительные остановки автоматически.

## 9. Спецификации: проверяйте результаты и замечания

Для каждой capability выполняется отдельный вызов автора. Несколько capabilities могут обрабатываться параллельно. Автор получает код, контекст проекта, правила и список объявлений. ChakChak проверяет учёт объявлений и структуру OpenSpec, после чего новая модель-читатель проверяет сценарии по реализации. Замечания могут вернуть черновик автору на ограниченное число кругов исправления.

На вкладке **Спецификации** находится дерево, в **Чате** — вызовы и сводки. Фильтры выделяют текущую работу, написанные документы, замечания, ошибки и ненаписанные спецификации. Завершённый вызов модели не равен завершённой спецификации.

| Результат | Как понимать |
| --- | --- |
| Написана | Спецификация сохранена. Рекомендательные замечания тоже стоит проверить. |
| Написана с замечаниями | Сохранённый результат содержит оставшиеся замечания по учёту или проверке. |
| Нужно исправить | В черновике или проверках остаются проблемы. |
| Не написана / отложена | Готовая спецификация этой capability не получена. Остальная работа может продолжаться. |
| Ошибка | Для этой capability произошла ошибка приложения. |
| Проверка ожидается | Спецификация сохранена, но чтение для проверки ещё не завершилось. |

У проблемной спецификации откройте **Разбор** из сводки вызовов или контекстного меню. Там собраны ошибки формы, учёт объявлений, вердикты по сценариям, пропущенные результаты и история вызовов. «Проверено», «противоречит коду» и «не показано кодом» описывают свидетельства читателя. Само по себе «не показано» — рекомендация к просмотру, а не доказательство отсутствия поведения.

Во время миграции через поле замечаний можно адресовать исправление одной спецификации либо сохранить правило для следующих. Новое общее правило не переписывает уже написанные документы. По состоянию результата доступны **Ещё круг**, **Повторить** или **Запустить снова**. Используйте действие конкретной capability, сохраняя успешную работу. Когда текущая волна остановлена, действие этапа **Повтор** повторяет неудачные попытки вместе.

После записи отчёта миграции её поле ввода больше не принимает исправления словами и новые правила. Повторы без дополнительных слов остаются там, где предложены. Чтобы изменить поведение, создайте OpenSpec change; правила для будущей работы можно изменить в конфигурации. У последующей сверки собственный процесс исправлений, и это ограничение закрытой миграции на неё не распространяется.

## 10. Остановка, пауза и восстановление

Во время написания спецификаций меню **Остановить** предлагает разные результаты:

| Действие | Что произойдёт |
| --- | --- |
| Прервать сейчас | Текущие вызовы отменяются, этап спецификаций встаёт на паузу. Сохранённые файлы остаются. **Продолжить** доделает остальное. |
| Не брать новые | Начатые capabilities дописываются и проверяются. Если работа остаётся, этап встаёт на паузу. |
| Завершить этап | Текущие вызовы отменяются, готовое сохраняется, записывается отчёт с ненаписанными спецификациями. |

**Продолжить** использует сохранённый прогресс. Спецификация, записанная перед остановкой, остаётся написанной; недостающая проверка читателя выполняется при продолжении. Намеренно остановленный запуск ждёт вас. Работу, прерванную аварийным завершением процесса, можно восстановить при следующем открытии репозитория.

При перегрузке модель повторно вызывается автоматически с растущими паузами; ожидание может занять примерно полчаса. **Повторить сейчас**, где предложено, пропускает текущую паузу. Ошибка входа, квоты или доступа к папке требует сначала устранить её причину. Страница предлагает действие для текущего состояния и сохраняет вывод провайдера в подробностях диагностики.

Если сохранённый разговор провайдера недоступен и автоматическое восстановление не помогло, используйте **Заново** с подсказкой «Начать разговор заново» в сообщении об этом отказе. После подтверждения создаётся новый разговор с сохранённым контекстом; принятые результаты остаются. Это не обычный способ исправления спецификации.

Если исчезло принятое распределение файлов, обычное продолжение блокируется, чтобы не угадывать его по неполному состоянию. Закройте активный процесс и сделайте копию рабочего пространства. Восстановите согласованный полный набор файлов либо используйте пригодный снимок этапа распределения через `chakchak stage cut` в терминале. Распределение и состояние запуска должны соответствовать друг другу.

Закрытие вкладки браузера само по себе не останавливает локальный процесс. **Настройки → Выключить** завершает его, сохраняя готовую работу. Если окно macOS только показывает процесс, запущенный отдельно, закрытие этого окна оставляет обслуживающий процесс работать.

## 11. Чтение отчёта

Экран отчёта показывает количество написанных спецификаций, файлов, вызовов модели и затраченное время. Кнопка **Отчёт** открывает полный Markdown-документ, **Карта кода** — исходный список. Наличие отчёта не устраняет замечания и незавершённую работу.

Прочтите отчёт перед тем, как считать миграцию завершённой. Проверьте отложенные capabilities, сохранённые сценарии с противоречиями, остатки учёта и замечания к распределению. Найденные во время написания предложения переместить файлы поступают на вашу проверку; они не меняют распределение молча. Применение изменения распределения может потребовать переписать затронутые спецификации.

**Открыть SDD** открывает рабочее пространство спецификаций. Отчёт бывает и у остановленного запуска, поэтому сама доступность этой кнопки не означает, что каждая capability уже описана.

## 12. Существующий репозиторий OpenSpec

ChakChak различает существующие спецификации и существующую миграцию ChakChak:

- **Локальное пространство и распределение ChakChak:** распознаётся сохранённый прогресс или завершённая миграция. Перемещение или клонирование папки не требует повторной миграции, если нужные файлы перенесены вместе с ней.
- **Локальное пространство со спецификациями без распределения ChakChak:** его можно просматривать в SDD. **Миграция** создаёт карту и распределение ChakChak; существующие спецификации используются как справочный материал, но не становятся принятым распределением. Существующий контекст проекта может позволить пропустить обзор.
- **Пространство из родительской папки или настроек OpenSpec:** ChakChak сообщает, что оно находится вне выбранной папки, и не мигрирует его. Выберите нужный корень либо явно создайте локальное пространство OpenSpec, если это соответствует структуре проекта.

Для продолжения текущий формат ожидает состояние ChakChak в `openspec/chakchak/`. Старые форматы разработки с состоянием запуска или распределением непосредственно в `openspec/` автоматически не преобразуются.

## 13. Сверка спецификаций после изменений кода

Представление спецификаций в SDD сравнивает репозиторий с последней сохранённой сверкой. Для этого модель не вызывается. **Синхронизировано** означает, что отслеживаемые входные данные и сохранённые свидетельства соответствуют записи; это не новая смысловая проверка и не запуск тестов.

Причиной расхождения могут быть изменения основного кода, добавленные или удалённые файлы, ручная правка `spec.md`, ненаписанная спецификация или отсутствующие данные связей и проверки. **Информация** объясняет причины, когда нужна синхронизация. При открытии изменённой спецификации могут отмечаться Requirements и Scenarios, затронутые изменением кода.

Чтобы выполнить сверку:

1. Изучите причину и убедитесь, что новые исходники отслеживаются Git и находятся внутри сохранённой области.
2. Нажмите **Синхронизация** в рабочем пространстве, чтобы открыть вопрос о согласии на запуск.
3. Проверьте список переписываемых capabilities и примерную стоимость. Выберите **Синхронизация** либо **Обсудить заново**, если сначала нужно изменить контекст проекта.
4. Проверьте распределение. Удалённые файлы убираются; для новых и нераспределённых может понадобиться вызов модели.
5. Дождитесь переписывания затронутых спецификаций и прочтите отчёт синхронизации.

Автор читает существующие спецификации, включая ручные правки, как материал, но восстанавливает поведение по коду. Ручные требования не гарантированно сохранятся после синхронизации. Изменение только содержимого отслеживаемого теста или ресурса не вызывает ту же проверку, что изменение основного кода; добавление или удаление файлов может иметь значение. Код, изменившийся ещё раз после начала синхронизации, может потребовать следующей сверки.

Capabilities, охваченные активными OpenSpec changes, ждут окончания этих изменений. Обычная сверка благодаря этому не переписывает незавершённую плановую работу. После архивации затронутые capabilities могут снова потребовать сверки. Новые корневые папки не добавляются в сохранённую область молча.

## 14. Создание изменения и подготовка документов

OpenSpec **change** — изменение — подходит для нового поведения, исправления или запланированного рефакторинга. Оно объединяет предложение, дельта-спецификации, проектное решение и задачи перед реализацией. Конкретные документы и зависимости задаёт выбранная схема.

### Создайте изменение

1. Откройте **Изменения** либо нажмите **Изменение** в синхронизированном представлении спецификаций.
2. Введите уникальное имя, например `add-catalog-search`: строчные латинские буквы, цифры и одиночные дефисы, первая буква — латинская. Не более 100 символов; `archive` зарезервировано.
3. Выберите схему. Изначально выбрана схема из конфигурации проекта.
4. Укажите входные данные и вложения, которые запрашивает форма выбранной схемы.
5. Нажмите **Изменение** с подсказкой «Создать новое изменение». Первый готовый к работе документ откроется на вкладке **Чат**.

Для документа без зависимостей опишите, что нужно сделать и зачем; пустого сообщения недостаточно. У последующих документов контекст уже есть в предыдущих материалах, поэтому дополнительные слова могут быть необязательными. При необходимости приложите файлы или изображения через поле ввода.

### Напишите, проверьте и подтвердите

Нажмите **Написать** для выбранного документа. Агент записывает предусмотренный схемой результат в папку изменения. Вкладка **Артефакт** показывает полученные документы; в чате находятся отчёт агента и доступные подробности его действий.

Каждый документ, написанный через ChakChak, после завершения вызова ждёт вашей проверки. Это относится и к задачам. Прочтите результат и выберите:

- **Подтвердить**, чтобы принять его и перейти дальше. Вопросы без ответа могут оставаться записанными; для подтверждения не обязательно отвечать на все.
- Ответьте на вопросы или добавьте исправления и нажмите **Доработать**. Агент обновит документ отдельным вызовом и снова остановится для проверки.

Существование файла не означает, что текущая или прерванная запись завершена. Для незавершённого документа предлагаются **Продолжить**, **Переделать** или **Принять как есть**. Продолжение просит агента закончить частичный результат; повтор начинает написание заново; принятие означает, что вы принимаете файл в текущем виде. Незавершённая или неподтверждённая зависимость блокирует документы, которым она нужна.

**Вернуться к шагу** у ранее написанного документа показывает, какие последующие документы придётся удалить перед его изменением. Осознанно подтвердите этот список. История чатов остаётся; удаление плановых документов не откатывает код, уже написанный по задачам.

## 15. Выполнение и проверка задач

Процесс задач ChakChak использует нумерованные строки с флажками в `tasks.md` на верхнем уровне папки изменения. После завершения планирования этап реализации превращается в отдельные ячейки задач в порядке файла. У каждой задачи должен быть уникальный номер. Поздние задачи можно читать, но они ждут отметок о завершении предыдущих.

Перед созданием задач для новых требований вопросник **Образцы** может предложить существующие основные требования и код в качестве примеров. Выберите подходящие варианты, укажите свои файлы относительно корня репозитория либо явно откажитесь от образца. Пропущенный вопрос сохраняет выбор по умолчанию, если подходящий кандидат есть. Неверный путь отклоняется, а не игнорируется молча.

Для каждой задачи:

1. Откройте её ячейку и прочтите задачу, а также инструкции `Files`, `Example`, `Check`, если они есть.
2. При необходимости добавьте указания и нажмите **Выполнить задачу**. Агент может менять код проекта, запускать команды и создавать коммиты задачи.
3. Изучите отчёт агента и вкладку **Изменения**. Она показывает коммиты и, где доступно, изменения в рабочем дереве. Большие и двоичные различия могут быть ограничены или пропущены с объяснением.
4. Выполните или проверьте подходящие проверки результата. Отметка завершения задачи не означает, что тесты прошли.
5. Нажмите **Готово**, когда результат вас устраивает. Это меняет флажок в `tasks.md` и разрешает выполнение следующей задачи.

Первой задаче нужно исходное состояние Git: репозиторий с первым коммитом и без посторонних неотслеживаемых файлов проекта вне `openspec/`. Если отказ называет такие файлы, решите, что должно войти в Git, а что нужно игнорировать, и самостоятельно подготовьте исходное состояние. ChakChak не создаёт его для задачи молча.

**Готово** становится доступно после коммита задачи либо после успешного ответа на проверочную задачу, которая не меняла файлов. Если агент изменил файлы, но не сделал коммит, попросите его закоммитить работу или повторите задачу. Если коммит уже есть, а флажка нет, проверьте результат и отметьте его; **Запустить снова** явно разрешает ещё одну попытку. Перед повтором завершённой задачи снимите её отметку.

Остановка задачи оставляет сделанные изменения в рабочем дереве. Она не отменяет их. У изменения одновременно выполняется одна операция записи; открытие другого шага не переводит туда работающего агента.

Некоторые внешние схемы отслеживают другой файл вместо `tasks.md` или не отслеживают задачи. Тогда ChakChak показывает прогресс OpenSpec только для чтения и не предлагает свои ячейки задач, чат задачи и редактирование флажков. Выполняйте реализацию обычным для этой схемы способом вне ChakChak.

## 16. Проверка, синхронизация изменения и архив

Эти шаги отличаются от **Синхронизации** кода и основных спецификаций в рабочем пространстве, описанной выше.

| Шаг изменения | Что проверить или сделать |
| --- | --- |
| Проверка — Verify | Изучить плановые документы, отметки задач, код, дельта-спецификации и конфликты. Проверить реализацию и результаты тестов. |
| Синхронизация — Sync | Сопоставить дельта-спецификации с основными назначениями, включая конфликтующие изменения. |
| Архив — Archive | Проверить остаток работы и завершить изменение средствами OpenSpec. |

Открытие панелей Verify и Sync не запускает агента или тесты. «Результат проверки не записан» и неизвестный результат синхронизации означают именно отсутствие подтверждённого результата. Наличие файлов, заполненный список задач и отсутствие заявленных конфликтов полезны для проверки, но не доказывают, что выполнялись тесты или отдельная команда синхронизации.

Если блокирующих замечаний нет, **Продолжить** сохраняет факт, что вы прошли шаг, и переводит дальше. Эта кнопка не выполняет проверки и не объединяет спецификации. Изменения состояния документов, задач и флажков могут сбросить такие отметки; ручная правка вне процесса всё равно требует вашей проверки.

На шаге архива **Завершить** вызывает стандартную архивацию OpenSpec. Операция переносит change в папку архива с датой и обновляет основные спецификации по правилам OpenSpec. При отказе причина остаётся на экране. После успешной архивации открывается рабочее пространство спецификаций; если оно показывает расхождение кода и спецификаций, выполните обычную сверку.

## 17. Настройка схем процесса

Область **Схема** показывает процессы, известные OpenSpec. Схема задаёт идентификаторы документов, зависимости, пути результатов, шаблоны и инструкции реализации. Начать можно со стандартного процесса; собственная схема добавляет документы, нужные команде.

Встроенные схемы доступны только для чтения. Создайте схему проекта на основе существующей либо импортируйте папку схемы. Редактируйте инструкции и шаблоны документов, порядок зависимостей, правила и указания для apply/archive. Подсказки полей объясняют настройки; форма показывает ошибки до сохранения.

Схемы, сохранённые или импортированные через ChakChak, должны включать вывод спецификаций, документ `tasks.md` и корректный шаг apply, отслеживающий `tasks.md`. В именах используются строчные латинские буквы, цифры и дефисы; пути должны оставаться внутри change. Зарезервированные имена операций `apply`, `verify`, `sync`, `archive` нельзя использовать как идентификаторы документов.

Изменение схемы активных changes может нарушить соответствие уже созданных документов новому процессу. Перед сохранением структурных правок прочтите предупреждение. Удалить можно только схему проекта, которую не использует конфигурация и активные changes. Удаляются сама схема и шаблоны; при необходимости восстанавливайте их через систему контроля версий.

## 18. Настройки, терминал и обновления

Откройте шестерёнку для просмотра **Настроек**. Закройте экран или нажмите Escape, чтобы вернуться.

- **Предпочтения:** язык интерфейса, светлая/тёмная/системная тема и движение. Они меняют интерфейс на этом компьютере.
- **Этот запуск:** репозиторий, язык спецификаций и его фиксация, агент, модель, доступные действия с папкой и терминалом.
- **О приложении / Обновления:** версия, **Проверить**, описание релиза и **Обновить**, когда доступно. Сборки для разработки не обновляются этим способом.
- **Команда в терминале:** установленная команда или ссылка и нужные инструкции для `PATH`, чтобы вызывать `chakchak`.
- **Открыть в браузере:** открывает тот же локальный интерфейс в браузере по умолчанию, где действие доступно.
- **Сбросить настройки:** переносит `settings.json` и пользовательский `agents.json` в файлы `.bak-<время>` (при совпадении имени добавляются `-2`, `-3`). Работа репозиториев, журналы и миграции остаются. Для загрузки стандартного набора агентов может понадобиться перезапуск.

В приложении нет переключателя автопилота. Автопилот включается в терминальном запуске; его сохранённое состояние может объяснять автоматическое принятие результатов без замечаний.

**Открыть в терминале** открывает терминал в репозитории. Рядом с показанной командой действие может сначала скопировать её. ChakChak не вставляет и не выполняет эту команду за вас.

Обновление скачивает и проверяет подходящий релиз, заменяет установленное приложение и перезапускает локальный процесс. Дождитесь остановки активной работы. Если приложение не может заменить себя, прочтите причину: например, macOS запускает временную копию из загрузок, папка установки защищена или файлы релиза недоступны. Вместо этого можно установить релиз вручную.

## 19. Сохранённые данные, коммиты Git и доступ

### Что находится в репозитории

Кроме стандартных результатов OpenSpec, в `openspec/chakchak/` находятся `run.json`, `codemap.jsonl`, `assignment.jsonl`, `scope.json`, `reconciliation.json`, отчёт, а в её дереве `specs/` — `trace.jsonl` и `verify.jsonl` отдельных capabilities. Сохраняйте согласованный набор состояния вместе с репозиторием, если коллеги должны продолжать миграцию и пользоваться переходами к коду.

Там же хранятся локальные разговоры, журналы, снимки этапов и состояния перед восстановлением. Правила игнорирования исключают локальную историю из обычных коммитов. Вложения исходного рассказа и чатов изменений копируются в игнорируемые папки ChakChak. Игнорирование Git не является шифрованием или ограничением доступа.

Журналы содержат запросы модели, ответы, диагностику и время. Сохраняются 20 новейших папок журналов и папки, изменённые за последние семь дней; более старые удаляются автоматически. Для разговоров, снимков, копий восстановления и вложений нет такой же автоматической очистки по возрасту или количеству; при долгой работе следите за объёмом истории.

### Что находится на этом компьютере

В `~/.chakchak/` находятся настройки, пользовательские провайдеры, установленная инструкция навыка, блокировки, временные файлы и журналы запусков без сохранённого состояния в репозитории. Временные данные репозитория удаляются, когда владеющий ими процесс освобождает репозиторий. Черновики интерфейса и часть настроек отображения также используют локальное хранилище браузера.

### Что попадает в коммиты

ChakChak может делать коммиты в текущей ветке для собственных записей OpenSpec: создание change, завершённая запись документа, отметка задачи, сохранение/импорт схемы, архив и результат миграции на этапе отчёта. Коммит включает файлы события и исключает `openspec/chakchak/**`; он не публикует ветку. Агент, реализующий задачу, делает собственные коммиты задачи.

Ошибка коммита не отменяет запись файла или архивацию. Прочтите уведомление и проверьте Git перед повтором. Автоматические коммиты ChakChak не добавляют за вас сохранённые данные связей и состояния: включайте нужные файлы `openspec/chakchak/` в обычную проверку и коммиты, сохраняя правила игнорирования.

### К чему имеет доступ агент

Интерфейс и сохранённое пространство локальны, но модельная работа выполняется через выбранного агента и настроенного в нём провайдера. Код, запросы и вложения могут отправляться этому провайдеру. Проверка и скачивание обновлений также обращаются к сервисам релизов.

Вызовы миграции просят только чтение и используют ограничения провайдера там, где они доступны. Это не универсальная гарантия песочницы для всех поддерживаемых CLI. Вызовы записи в SDD работают с широкими правами, загружают обычную конфигурацию агента и доступные интеграции и не ждут интерактивного разрешения каждого инструмента. Они могут менять файлы, выполнять команды и пользоваться подключёнными сервисами согласно конфигурации. До задачи настройте агента и его MCP-серверы соответствующим образом.

Флажки области не ограничивают эти права. Проверяйте материалы перед прикреплением. Перед отправкой диагностического отчёта просмотрите выбранное содержимое: локальные журналы могут включать сведения о репозитории и сообщения модели, даже если показанный вывод скрывает некоторые значения, похожие на секреты.

## 20. Практические вопросы

### Почему нового файла нет в карте?

Проверьте отслеживание Git, сохранённую область папок и поддержку парсера. Дерево файлов может показывать неотслеживаемый файл, который карта намеренно исключает. Новая корневая папка не включается в последующую сверку автоматически.

### Почему тестовых файлов ноль?

Тестовые папки могут быть исключены, файлы могут не отслеживаться Git, либо **Тесты — тоже продукт** учитывает их как основной код. Проверьте область и карту, прежде чем делать вывод о наличии тестов.

### Почему следующий этап не начался?

Обычная миграция ждёт исходный рассказ, принятие описания, инструкции распределения, проверку распределения и инструкции спецификаций. Change ждёт подтверждения документов и отметок задач. Откройте текущий этап и выполните предложенное действие: спокойный экран часто означает намеренную остановку для проверки.

### Можно ли уйти из приложения, пока оно работает?

Можно смотреть сохранённые документы, не перезапуская работу. Закрытие только вкладки браузера оставляет процесс работать. Для паузы используйте остановку, для завершения приложения — выключение. Уже сохранённые результаты будут доступны при следующем запуске.

### Зелёный цвет означает, что программа работает правильно?

Нет. Сохранённая спецификация, проверка структуры, проверка сценария, отметка задачи и выполненные тесты — разные факты. Для нужного вывода проверяйте соответствующие свидетельства.

### Можно ли править спецификации вручную?

Да, это обычные Markdown-файлы. Следующая сверка заметит правки и может переписать спецификации по коду. Для желаемого поведения используйте change, для проверки и восстановления правок — Git.

### Можно ли дальше работать без ChakChak?

Да. Основные спецификации, changes, схемы и конфигурация — обычные документы OpenSpec. Сохраняйте метаданные ChakChak, если нужны продолжение его запусков, сверка и навигация по свидетельствам.

### Провайдер сообщает об ошибке входа, квоты или доступа. Что делать?

Исправьте вход, доступ к модели, квоту или разрешения папки средствами самого провайдера. Затем повторите неудавшееся действие в ChakChak. Смена языка интерфейса и повторное открытие документа не устраняют отказ провайдера.

### Как полезно сообщить об ошибке?

Запишите версию ChakChak, операционную систему, выбранного агента и модель, нажатое действие, ожидаемое поведение, фактическое сообщение и наличие сохранённых файлов. Если в приложении доступен отчёт разработчику, воспользуйтесь им и проверьте содержимое перед отправкой. При разборе прерванного запуска сохраните копию состояния репозитория.
