# Агенты, терминальные команды и MCP

[Документация](README.md) · [English](../integrations.md) · [Установка](installation.md) · [Решение проблем](troubleshooting.md)

У агента возможны две роли. **Провайдер** отвечает на подготовленные модельные задания ChakChak. **Управляющий агент** через MCP занимает место человека и принимает решения. `chakchak mcp` может использовать эту же сессию как провайдера или поручить модельные вызовы указанному локальному CLI.

## Провайдеры

Ниже перечислены встроенные интеграции. Наличие провайдера в таблице не означает, что проверена каждая версия его CLI. Установите и авторизуйте провайдера отдельно; ChakChak запускает существующую программу и не управляет её данными входа.

|---|---|---|---|---|
| Claude Code | `claude` | CLI/stream JSON | `.claude` | Да |
| Codex | `codex` | CLI; app-server для записи/каталога | `.codex` | Да |
| Gemini CLI | `gemini` | ACP | `.gemini` | Да |
| Qwen Code | `qwen` | CLI; stream JSON с разрешениями при записи | `.qwen` | Да |
| OpenCode | `opencode` | ACP | `.config/opencode` | Да |
| Crush | `crush` | CLI | `.config/crush` | Да |
| Cursor CLI | `cursor-agent` | ACP | `.cursor` | Да |
| GitHub Copilot CLI | `copilot` | ACP | `.copilot` | Да |
| Kimi CLI | `kimi` | ACP | `.kimi-code` | Да |
| Qoder CLI | `qodercli` | ACP | `.qoder` | Да |
| Kiro CLI | `kiro-cli` | CLI | `.kiro` | Да |
| Cline CLI | `cline` | ACP | `.cline` | Да |

ACP — Agent Client Protocol через локальный дочерний процесс. ACP провайдера и MCP-интерфейс самого ChakChak — разные соединения.

Папка конфигурации выбирается в порядке: переменная провайдера, затем его `homeUnderConfig` внутри `XDG_CONFIG_HOME`, затем стандартный путь таблицы. Объявлены переменные `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `COPILOT_HOME` и `KIMI_CODE_HOME`. `homeUnderConfig` указан у Claude Code, OpenCode, Crush, Kilo, Amp и Goose. Если строка объявляет `skills`, загрузчик находится в `<папка конфигурации>/skills/chakchak/SKILL.md`.

### Поиск и выбор программы

Каждый запуск один раз читает окружение login shell через `$SHELL -lic` с пределом десять секунд. Он добавляет недостающие переменные и дописывает каталоги login `PATH` после собственных. В журнал попадают имена добавленных переменных, но не значения. Так запуск с рабочего стола находит настроенные в shell инструменты.

Приложение показывает найденные копии агентов и их пути; выберите нужную. Выбор сохраняется с абсолютным путём. При открытии сохранённого запуска этот выбор приложения имеет приоритет; прежний агент запуска используется как запасной, если выбора нет или выбранная программа исчезла. При смене провайдера обсуждение продолжается по сохранённому результату. CLI принимает имя программы или путь после `cli`, `web`, `mcp`. Перед запуском дочернего процесса символические ссылки разрешаются, чтобы агент нашёл вспомогательные файлы рядом с реальным исполняемым файлом; интерфейс сохраняет привычный путь. Журнал содержит заданный и разрешённый пути.

ChakChak не угадывает новые флаги через произвольные вызовы `--help` или проверки входа. Список моделей запрашивается через протокол каталога, объявленный в строке: Claude stream JSON, Codex app-server, Qwen-family stream JSON или ACP. Без каталога имя модели вводится вручную. Ошибка каталога показывается отдельно от результата поиска программы.

### Модели, effort и параллелизм

`--model <name>` явно задаёт модель для CLI/web/MCP с провайдером. Иначе вызов использует выбор для этой программы в памяти текущего процесса, а если его нет — модель по умолчанию у провайдера. Выбор модели не записывается в `settings.json` и не восстанавливается из атрибуции старого запуска; после перезапуска выберите модель заново, если нужна конкретная. Сохранённый выбор агента и модель записанного запуска — разные данные. ChakChak не добавляет флаг reasoning effort.

Предел параллельных вызовов равен восьми, если `--parallel <1-8>` не задаёт меньший. Фактический темп начинается с ранее изученного значения для агента или одного вызова, растёт после успешных вызовов и уменьшается вдвое при перегрузке. Темп и оценки длительности сохраняются в настройках. Повышение предела не запускает восемь вызовов сразу. Каждому вызову приписывается модель, которую назвал провайдер; trace и отчёт сохраняют эту информацию.

## Права и внешние сервисы

Каждый процесс агента работает в репозитории. Задание передаётся через stdin либо через `{task}`, если строка требует аргумент команды. Миграция — обсуждение, разбиение, написание и чтение спецификаций — использует **режим чтения**. Чаты изменения и задачи используют **режим записи** с широкими правами провайдера.

| Провайдер | Миграция/чтение | Запись в чатах изменения/задачи |
|---|---|---|
| Claude Code | `--safe-mode --permission-mode dontAsk --disallowedTools Write,Edit,MultiEdit,NotebookEdit,Bash` | `--dangerously-skip-permissions` |
| Codex | `--sandbox read-only --ignore-user-config --ignore-rules` | Сессия app-server с полными правами; в строке также объявлен `--dangerously-bypass-approvals-and-sandbox` для CLI-записи |
| Qwen Code | `--approval-mode plan` | `--approval-mode auto-edit`, заранее разрешённые встроенные/MCP-инструменты и ответы на запросы прав в потоке |
| Провайдеры ACP | Разрешаются запросы инструментов только для чтения, остальные отклоняются | Выбирается allow-once |
| Остальные CLI-строки | Объявленные `read`-флаги, если они есть | `write`-флаги или базовая команда |

Защита чтения зависит от объявленных флагов/протокола провайдера. Строка без отдельного ограничения чтения полагается на инструкцию задания; независимую файловую песочницу ChakChak не создаёт. Некоторые строки включают разрешающие флаги прямо в базовую команду. Проверьте строку перед работой с чувствительным репозиторием.

Вызовы записи загружают настройки провайдера, инструкции проекта, hooks, навыки и MCP-серверы. Они могут менять файлы, выполнять инструменты и влиять на внешние сервисы в пределах прав провайдера. Задание просит агента закоммитить выполненную задачу с trailer `Task: <change> <number>`; сам ChakChak читает эти коммиты. Остановка оставляет правки агента в дереве. Git не отменит действия внешних сервисов, раскрытие секретов, изменения вне репозитория или уничтожение `.git`.

Вызовы записи SDD выполняются без интерактивного ожидания человека. На вопросы провайдера отвечает интеграция. На MCP-вопрос Codex может ответить короткий модельный вызов; просьбы о пароле, ключе, токене или секрете отклоняются. Уведомления о правах видны в чате. Qwen заранее разрешает инструменты и отвечает на permission-control; запрещающее правило самого провайдера всё ещё может отказать инструменту. В метаданных этих строк отдельные части явно помечены непроверенными: таблица не гарантирует совместимость всех версий.

Код и материалы задания могут уходить выбранному модельному провайдеру. Локальный web-интерфейс не означает локальную модель. Авторизация, оплата, хранение данных и подключённые сервисы остаются свойствами выбранного агента/провайдера.

## Собственные провайдеры и замены

Для неизвестной программы терминал может спросить пример команды на одно задание; в приложении можно добавить программу и пример вызова. Поставьте `{task}` на место задания либо не указывайте его, чтобы передать задание через stdin. Такие вызовы сохраняются в настройках. Структурированная строка нужна для отдельных режимов чтения/записи, ответа не через stdout или каталога моделей.

`~/.chakchak/agents.json` принимает массив строк или объект с массивом `known`. Совпадающий `program` **заменяет встроенную строку целиком**, а не отдельные поля; новый добавляется. Неизвестные JSON-поля и некорректные определения отклоняются. Для ясности храните одну замену на программу; перед изменением существующего override сохраните копию.

Пример условной программы, которая читает stdin и печатает ответ:

```json
{
  "known": [
    {
      "program": "my-agent",
      "title": "My Agent",
      "home": ".my-agent",
      "skills": "skills",
      "run": ["ask", "--model", "{model}"],
      "read": ["--read-only"],
      "write": ["--allow-writes"],
      "answer": "stdout"
    }
  ]
}
```

Флаги в примере условные: замените их настоящим неинтерактивным интерфейсом программы. Доступные поля строки провайдера:

| Поле | Значение |
|---|---|
| `program`, `title` | Имя исполняемого файла и отображаемое название |
| `run` | Массив аргументов с `{model}`, `{task}`, `{answer}` |
| `read`, `write` | Дополнительные аргументы соответствующего режима |
| `answer` | `stdout`, `file` (нужен `{answer}`) либо `json:<field>` |
| `acp` | Аргументы запуска ACP вместо `run`/answer/read/write |
| `resume` | Продолжение JSON-stream разговора с одним `{thread}` |
| `home`, `homeEnv`, `homeUnderConfig`, `skills`, `installs` | Пути поиска и регистрации |
| `catalog` | Протокол списка моделей, аргументы и подтверждающая ссылка `why` |
| `mcp` | Команда списка серверов провайдера и формат `lines` или `json:<field path>` |
| `appserver`, `grant` | Специальное управление сессиями/правами; ориентируйтесь на существующие строки и реализацию |

Если модель отсутствует, удаляются `{model}` и предыдущий аргумент. Не храните здесь или в аргументах пароли и токены: используйте авторизацию провайдера. После изменения override перезапустите ChakChak.

## Команды и флаги

Репозиторные команды запускайте из корня нужного репозитория. Просто `chakchak` запускает терминальный режим; для флагов нужно явно написать `cli`, `web` или `mcp`.

| Команда | Действие |
|---|---|
| `chakchak cli [program-or-path] [--model name] [--parallel 1-8] [--lang en\|ru] [--strict]` | Начать/продолжить терминальную миграцию или синхронизацию |
| `chakchak web [program-or-path] [--model name] [--parallel 1-8]` | Интерфейс этого репозитория в браузере |
| `chakchak app` | Выбор репозитория/приложение |
| `chakchak mcp [program-or-path] [--model name] [--parallel 1-8]` | MCP через stdin/stdout |
| `chakchak specs [capability]` | Прочитать рабочую область или одну полную спецификацию без модели |
| `chakchak stage <map\|talk\|picture\|cut\|specs\|report> [capability\|--all]` | Повторить этап; последний аргумент допустим только у `specs` |
| `chakchak fix <capability-or-number> ["исправление"]` | Переписать сохранённую спецификацию; без слов спросить исправление |
| `chakchak rule "слова"` | Добавить правило для последующих записей спецификаций |
| `chakchak accept <n…>\|all`, `chakchak reject <n…>\|all` | Отметить предложения разбиения после запуска; пока ничего не переписывать |
| `chakchak apply [<n…>\|all]`, `chakchak dismiss <n>` | Применить принятые предложения вместе либо отклонить одно |
| `chakchak new-conversation [--confirm]` | Архивировать checkpoint и начать разговор с сохранённым контекстом; без флага спросить подтверждение |
| `chakchak install`, `doctor`, `uninstall` | Установить, проверить или удалить загрузчики навыка |
| `chakchak skill`, `help`, `version` | Напечатать инструкцию, справку или версию без журнала |

`--lang` доступен только CLI и задаёт язык обсуждения/спецификаций/отчёта до фиксации подготовки; язык терминального интерфейса он не меняет. Web использует настройки, MCP — язык экранов. `--strict` также только для CLI: обычное завершение возвращает 0 даже с открытыми/неудавшимися спецификациями; strict возвращает 3, если остались unwritten/open/failed/pending. Остановка человеком возвращает 2; ошибка запуска/отказ либо проваленный/заблокированный этап — 1. Читайте итоговую сводку вместе с кодом возврата.

Внутри терминала `help` показывает действия текущего вопроса, `show` повторяет текст, `auto` включает/выключает принятие вариантов по умолчанию. На разбиении есть ручной `move`; при записи спецификаций доступны `stop`, `end`, `fix`, `rule`. Доступность зависит от этапа, поэтому ориентируйтесь на показанные варианты. `NO_COLOR=1` отключает цвет. Перенаправленный stdout или `TERM=dumb` отключает escape-последовательности и печатает самостоятельные строки событий.

## Установка навыка агента

```sh
chakchak install
chakchak doctor
```

Install показывает агентов, точные пути и текст загрузчика, затем предлагает номера, `all` или `none`. Записываются только выбранные загрузчики. Для вступления регистрации в силу откройте новую сессию агента.

Загрузчик при каждом вызове навыка запускает установленный исполняемый файл по **абсолютному пути** с `skill` и читает его полную инструкцию. Поэтому обновление на прежнем месте сохраняет работоспособность навыка. После перемещения программы/приложения нужен новый install. Уже загруженная инструкция в текущем разговоре не обязана обновляться сразу.

Install может заменить распознанный навык ChakChak с полностью совпадающим frontmatter, включая изменённое тело, без резервной копии. Чужие/нераспознанные файлы сохраняются. `uninstall` удаляет только точный неизменённый текущий загрузчик. `doctor` сообщает состояние регистрации, не меняя файлы навыков провайдера; как рабочая команда он может создавать собственные журналы/состояние ChakChak.

**Install не настраивает MCP.** Навык и MCP-соединение клиента — разные вещи. `chakchak skill` печатает полную текущую инструкцию без записи; рабочие запуски также поддерживают её копию в `~/.chakchak/SKILL.md`.

## Подключение MCP

В MCP-клиенте настройте **командный сервер stdio** со следующими параметрами:

| Настройка | Значение |
|---|---|
| Исполняемый файл | Абсолютный путь к `chakchak`, например `/Applications/ChakChak.app/Contents/MacOS/chakchak` |
| Аргументы в session mode | `mcp` |
| Аргументы с провайдером | `mcp`, затем установленный провайдер, например `codex` |
| Рабочая папка | Абсолютный путь к целевому репозиторию |
| Окружение | Нужное провайдеру окружение; обычные переменные home/config должны сохраняться |

У ChakChak нет флага `--cwd` и HTTP-точки MCP. Задайте рабочую папку средствами клиента либо обёрткой, которая делает `cd` и затем `exec` программы. Синтаксис и путь файла конфигурации зависят от клиента; ChakChak их не создаёт и не переписывает. Не подключайте HTTP MCP к адресу страницы браузера. Stdout занят протоколом, диагностика и адрес страницы наблюдения идут в stderr.

Используйте текст передачи из `chakchak help`: прочитать/сохранить навык через `skill` абсолютного исполняемого файла, подключить его `mcp` по stdio в репозитории и мигрировать этот репозиторий. Если клиент не умеет задавать cwd, можно использовать исполняемую shell-обёртку:

```sh
#!/bin/sh
cd '/absolute/path/to/repository' || exit 1
exec '/absolute/path/to/chakchak' mcp
```

Укажите путь обёртки как исполняемый файл MCP-клиента. Для каждого репозитория используйте отдельное соединение. Навык указывает на бинарный файл, поэтому MCP и навык должны относиться к одной установке.

### Жизненный цикл и инструменты MCP

Подключение, список инструментов и idle-status не захватывают репозиторий. `start` получает владение папкой и готовит восстановление; если она занята, возвращается `busy`, но соединение остаётся пригодным для повтора. Владение сохраняется до закрытия сессии. После старта доступна страница наблюдения на loopback, где человек может только остановить или завершить работу.

| Группа | Инструменты и назначение |
|---|---|
| Сессия | `start`, `status`: вопрос, revision, ход работы и фоновые команды |
| Решения миграции | `accept`, `say`, `move`, `fix`, `rule`, `proposal`, `stage`, `stop`, `restart_conversation` |
| Очередь модели сессии | `tasks`, `answer`: получить подготовленные задания и ответить |
| Чтение рабочей области | `specs`: актуальность, изменения, новые/нераспределённые файлы или полная спецификация |
| Изменения OpenSpec | `schema` читает схемы/настройки; `change` создаёт заготовку с необязательными ответами/вложениями |
| Промпты и примеры | `artifact`, `task`, `examples`: вернуть промпт или примеры кода без запуска агента |

Точные параметры берите из `tools/list` установленной версии. Терминальный `accept <n>` отмечает предложения, а MCP `accept` отвечает на текущий вопрос; отметками и применением предложений занимается MCP `proposal`.

Перед решением читайте `status`. Инструменты с revision отказывают устаревшей версии и возвращают текущую; сначала перечитайте вопрос, затем повторяйте действие. `status` с `wait`/`since` ждёт изменения, задания или завершения команды; после `unchanged` можно ждать снова. `idle` означает, что работа сдвинется только от действия клиента. `fix` и `rule` возвращаются раньше завершения фонового модельного вызова: проверяйте `status.commands` и обслуживайте очередь. `stage` откажет при конкурирующей работе.

**Без указанного провайдера** `start` принимает `model` для атрибуции сессии, а работа приходит через `tasks`. Полностью отвечайте через `answer` в формате конкретного задания; quota/login/network/overload передавайте структурированным отказом. После потери исполнителя/сессии `tasks` с `retake: true` повторно выдаёт взятые задания без ответа. `stop` отменяет незавершённые задания. **С указанным провайдером** его CLI запускает ChakChak, а инструменты очереди сообщают, что недоступны в этом режиме.

`start` напрямую продолжает прерванный/проваленный запуск посреди этапа. Новая миграция или законченный репозиторий, требующий синхронизации, может показать вопрос Start; следуйте его тексту и получите согласие человека там, где этого требует навык. Актуальные спецификации не требуют модельных вызовов. `restart_conversation` требует текущие revision, proof из status и явное `confirmed: true`; прежде чем заменить разговор, он архивирует checkpoint.

`artifact` и единственное число `task` возвращают промпт: они не выполняют его, не захватывают право записи и не проверяют последующие изменения вызывающего агента. `tasks` — отдельная очередь миграции. Явно выбранный артефакт может быть недоступен из-за предыдущего или незавершённого шага. `examples` только читает код. `change` записывает обычную заготовку OpenSpec и переданные ответы/вложения; `schema` и `specs` только читают. Управляющий агент записывает решения и основания в `chakchak-decisions.md` в корне репозитория, за пределами восстанавливаемого по этапам `openspec/`.

## Навыки и MCP-серверы для изменения

Приложение может перечислить личные и проектные навыки выбранного агента; одноимённый проектный имеет приоритет, а собственный загрузчик ChakChak исключён. Этот список не устанавливает навыки.

Серверы MCP читаются объявленной командой провайдера, например `codex mcp list --json` или `claude mcp list`; сохраняются только имена серверов. У части строк команда помечена непроверенной. Получение списка ограничено 20 секундами, поскольку провайдер может проверять доступность каждого сервера. Настраивайте и авторизуйте серверы у провайдера. Схема может указывать MCP-сервер и запрашивать подсказки/вложения: прочитайте `schema` и передайте необязательные значения при создании изменения. Если управляющему агенту недоступен нужный артефакту сервер, подключите его до исполнения промпта.
